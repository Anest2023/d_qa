План

Иссследование приложения (App Exploration, Prodact Analisis)

1 этап: изучить доступную документацию

Дано:

- Описание приложения

  Приложение даёт функционал по работе с новостями хосписа и включает в себя:

1) информацию о новостях и функционал для работы с ними;
2) тематические цитаты;
3) информацию о приложении.

- Описание API

  Проект работает на Android API 29.

- Изображение экрана

https://github.com/netology-code/qamid-diplom/blob/main/pic/app.png


4) Инструменты тестирования

- Android Studio Emulator – запуск и ручное тестирование приложения на разных версиях Android.
- Espresso + JUnit – написание и выполнение UI-автотестов.
- Allure – формирование отчётов о прохождении автотестов.
- Google Sheets – ведение чек-листов и тест-кейсов.
- Git / GitHub – хранение кода тестов и документации.

5) Устройства/эмуляторы, на которых проводится тестирование
- эмулятор Pixel 9, Android 16.0 (Baklava), arm64

2 этап: установка и первичный "Smoke Test"

1) установить приложение на эмулятор
2) начать пользоваться приложением и составить ментальную карту тоого, что вижу:

- сколько основных экранов (главная, новости, цитаты, профиль)
- что происходит при первом запуске (требуется вход илли нет?)
- кликабельные и некликабелные элементы

3 этап:

1) составить Mind Map (карту функциональности)
2) определить что именно будет проверяться в соответствии с типами тестирования
2) составить чек-лист: предварительный список проверок
3) составить тест-кейсы (далее дополнять их)

4 этап:

1) определить, какие проверки следует автоматизировать1. Авторизация и выход
    - 1А Авторизация с валидными данными
    - 1B Выход из приложения

2. Навигация и чтение новостей
    - 1-M-1 Переход на страницу News через кнопку ALL NEWS
    - 1-NN-1 Переход на страницу News через верхнее меню
    - 2-NNR-1 Чтение первой новости
    - 1-MN-1 Просмотр первой новости через выпадающий список на странице Main
    - 1-MN-2 Чтение последней новости через выпадающий список на странице Main
    - 2-NNR-1 Чтение первой (сверху) новости на странице News
    - 2-NNR-2 Чтение второй (сверху) новости на странице News
    - 2-NNR-3 Чтение последней (сверху) новости на странице News

3. Сортировка и фильтрация

- 3-NNS-1 Сортировка по дате (переключение)
- 4-NNF-1 Переход на страницу фильтрации
- 4-NNF-2 Фильтр по категории
- 9-CPFN-3 Фильтр по категории + диапазон дат
- 9-CPFN-4 Только начальная дата (ошибка)
- 9-CPFN-5 Только конечная дата (ошибка)
- 8-CPS-1 Сортировка на странице Control panel

4. Создание новостей (позитивные и негативные сценарии)
 -  5-NNC-2 Переход на форму создания новости
 - 5-NNC-3 Успешное создание новости (все поля)
 -  5-NNC-4 Только категория – остальные поля пустые (ошибки)
 -  5-NNC-5 Пустая категория (ошибка)
 -  5-NNC-6 Пустой заголовок (ошибка)
 -  5-NNC-7 Пустая дата (ошибка)
 -  5-NNC-8 Пустое время (ошибка)
 -  5-NNC-9 Пустое описание (ошибка)
 -  5-NNC-10 Все поля пустые (ошибки)
 -  5-NNC-11 Отмена создания (Cancel → OK)
 -  5-NNC-13 Отмена закрытия формы (Cancel → Cancel в диалоге)

5. Редактирование новостей
 -  6-NCPEN-1 Редактирование всех полей
 -  6-NCPEN-3 Редактирование только заголовка
 -  6-NCPEN-4 Редактирование только даты
 -  6-NCPEN-5 Редактирование только времени
 -  6-NCPEN-6 Редактирование только описания
 -  6-NCPEN-2 Редактирование поля Category связано с багом (автоматическое изменение Title).
   Автоматизация этого теста возможна после справления бага.

6. Удаление новостей
 -  7-NND-1 Удаление новости со страницы Control panel
 -  7-NND-2 Проверка, что новость исчезла из News

7. Цитаты
 -  10-L-1 Открытие списка цитат
 -  10-L-2 Раскрытие цитаты
 -  10-L-3 Закрытие цитаты при повторном клике
 -  10-L-4 Возвращение на предыдущую страницу при повторном клике по иконке Бабочка: возможно
 - автоматизировать после исправления бага
 -  10-L-5 Свайп вправо (возврат)
 -  10-L-7 Переход на Main через меню


2) составить план подготовки к автоматизации проверки приложения (настроить проект, подключить
   библиотеки и т.д.)

5 этап:

1) написать и выполнить автотесты
2) заполнить чек-лист
3) заполнить тест-кейсы
4) составить баг-репорт (если будут выявлены ошибки в работе приложения)

6 этап:

1) составить отчет
2) отправить отчет на проверку
